Getting started

Build the app, connect it to an NTmart database and sign in with an existing NTmart user account.

Preview edition. NTmart POS Go has no licence enforcement yet, so don't give it to clients. Use it on a test copy of the database, alongside the PHP edition, until Phase 8 ships.

On this page: Requirements · Build and run · Connect to the database · Running next to PHP · For developers

Requirements

ItemDetails
Operating systemWindows (native Win32 app)
DatabaseMySQL or MariaDB with the NTmart schema, the same database the PHP edition uses
AccountAn existing NTmart user account
Receipt printerOptional: an ESC/POS thermal printer, 80mm or 58mm
To build from sourceGo toolchain and PowerShell

Build and run

  1. Build the app. From the project folder, run the build script in PowerShell. It produces NTmartPOS.exe. 
    .\build.ps1
  2. Start it. 
    .\NTmartPOS.exe
  3. Sign in with an existing NTmart user account. Passwords, lockout and the audit log work the same as in the PHP edition.

Connect to the database

On first run the app asks for the database server. The defaults are:

Serverlocalhost:3306
Userroot
Databasentmart

The details are saved to %APPDATA%\NTmartGo\config.json. To change them later, click Database... on the sign-in screen.

Running next to PHP

The Go edition reads and writes the existing NTmart tables exactly as the PHP edition does, so both can run on the same database at the same time.

  • No data migration: your data is already where the Go app expects it.
  • Schema changes stay with the PHP migrations, so the two editions always agree on table shapes.
  • Some features still run through PHP for now. For example, Go queues eTIMS submissions and the PHP edition transmits them.
  • Dates are stored as the shop's local time, just like the PHP edition.

For developers

Unit tests run on their own. The integration tests also need a database. Point NTMART_TEST_DSN at a disposable copy such as ntmart_godev:

$env:NTMART_TEST_DSN = 'root@tcp(localhost:3306)/ntmart_godev?parseTime=true&charset=utf8mb4'
go test ./...

The integration tests insert and delete rows. Never point them at a client database.

House rules

  • Money is exact. Use shopspring/decimal for every amount and quantity, never float64.
  • One shape for money queries. Read the *_splits tables, exclude contra settlements, and negate refunds rather than summing them. Copy the PHP query instead of re-deriving it.
  • Use the database clock (NOW()) for anything compared against other timestamps.
  • Multi-step writes go in one transaction, with deadlock retry and idempotency keys.
